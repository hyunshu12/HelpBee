## 3. 데이터 — `cases.json` 스키마 확장

```jsonc
{
  "id": "dwv-1",
  "photo": "photos/dwv-1.jpg",
  "kind": "visible" | "varroa" | "healthy",   // ★ 신설 — 라운드 배정 키
  "disease": "dwv" | "chalkbrood" | "varroa" | null,   // ★ 신설
  "diseaseLabel": "날개불구 바이러스",          // ★ 신설 — 화면 표시명
  "imageWidth": 1920, "imageHeight": 1080,
  "riskScore": 0,          // 응애 감염률 기반. kind=visible 이면 0 (응애 없음)
  "tier": "safe" | "watch" | "danger",   // kind=visible 은 아래 규칙으로 별도 산출
  "beeTotal": 9,
  "sickCount": 4,          // ★ varroaCount → sickCount 로 일반화 (응애 or 다른 병)
  "recommendations": [...],
  "boxes": [{ "x", "y", "w", "h", "cls": "varroa" | "disease" | "normal" }]   // ★ disease 추가
}
```

**kind=visible 의 tier**: 응애 감염률 함수(`compute_risk`)는 응애 전용이라 그대로 못 쓴다.
부스 한정으로 `sickCount / beeTotal` 에 같은 밴드(3% / 10%)를 적용해 tier 를 낸다.
생성기 주석에 "부스 전용 규칙, 제품 로직 아님"을 명시한다. 게이지는 그리지 않으므로
riskScore 는 화면에 안 나간다.

**recommendations (visible)**: 생성기에 병별 정적 문구 2~3줄. 예:
- dwv: "날개불구 바이러스는 응애가 옮깁니다. 응애 방제를 먼저 확인하세요."
- chalkbrood: "석고병은 습하고 추울 때 번집니다. 벌통 환기와 보온을 점검하세요."

**라운드 배정**: 세션 시작 시 풀에서 `kind` 별로 하나씩 랜덤 → `[visible, varroa(danger), varroa(watch) | healthy]`.
R3 는 응애 주의 2장 + 정상 2장 = 4장 중 하나 (정상 확률 50%).
같은 세션에 같은 사진이 두 번 나오지 않는다 (R2 는 danger 만, R3 는 watch/healthy 만이라 자연히 겹치지 않음).

**사진 선정** (구현 시 눈으로 최종 확인):
| id | 출처 | 비고 |
|---|---|---|
| dwv-1, dwv-2 | `성충_날개불구/015`(4/9), `/007`(2/13) | 벌통 사진에 감염 벌 여러 마리 |
| chalk-1 | `유충_석고병/044`(15/17) | 소방 15칸이 하얗게 굳음 |
| danger-100, danger-90, danger-3 | 기존 2 + 신규 1 | 신규는 `성충_응애` 에서 응애 2마리 이상·박스 겹침 없는 것 |
| watch-50, watch-2 | 기존 1 + 신규 1 | 신규는 응애 1마리 / 전체 10마리 이상 (감염률 3~10%) |
| safe-0, safe-2 | 기존 1 + 신규 1 | 신규는 `성충_정상` 벌통 사진, 벌 6마리 이상 |

신규 4장은 **구현 1단계에서 xyxy 기준으로 선정**한다 (이전 세션의 후보 danger-83·safe-076 은
xywh 오해석으로 뽑혔던 것이라 재검토 대상). 선정 기준은 `2026-08-30_부스체험앱-설계.md` §4.

생성기 `make_booth_cases.py` 가 `kind`/`disease` 를 spec 에서 받아 채운다.
`cls` 매핑: `CLASS_VARROA`→`varroa`, `CLASS_OTHER_DISEASE`→`disease`, 나머지→`normal`.

## 4. 화면

### 4.1 투어 시작 (신설, 가벼움)
헤드라인 한 줄 + 부제 + 주 버튼 `시작하기`. 사진 없음. 5초 안에 지나가는 화면.

### 4.2 추측 (기존)
상단 우측에 `1 / 3`. 그 외 동일. 안내 라벨(eyebrow) 제거.

### 4.3 분석중 (기존, 4초로)
단계당 1.3초. 스캔 라인 유지.

### 4.4 결과 (기존, 종류별 분기)

| kind | 판정 영역 | 박스 색 |
|---|---|---|
| varroa | 게이지 + 티어 배지 + "N마리 중 M마리 감염 의심" (현행) | 빨강 |
| visible | **게이지 없음.** 병 이름 크게 + "의심 개체 N마리 / 전체 M마리" + 티어 배지 | **주황** |
| healthy | 게이지 0 + 안전 배지 + "감염 의심 개체 없음" (현행) | 초록 |

범례: 응애 · 다른 병 · 정상 (3색).

**대조 카드 문구** — (라운드 성격, 맞음/틀림) 조합:
| 상황 | 문구 |
|---|---|
| visible 맞음 | 잘 보셨어요. 이건 눈에 보이는 병입니다. |
| visible 틀림 | 놓치셨네요 — 날개를 다시 보세요. (병별 힌트 한 줄) |
| varroa 맞음 | 맞히셨네요! 그런데 어디가 문제인지 보이셨나요? |
| varroa 틀림 | 못 찾는 게 정상입니다. 응애는 2mm예요. |
| healthy 맞음 | 의심하지 않고 잘 보셨네요. 정말 건강합니다. |
| healthy 틀림 | 함정이었습니다 — 이 벌통은 건강합니다. |
| 추측 건너뜀 | (대조 카드 없음, 현행) |

버튼: 주 버튼 `다음 사진 →` (R3: `결과 보기 →`). 보너스 경로에서는 `마치기 →`.
`기록 보기`·`다른 사진 해보기`·`QR 받기` 제거.

### 4.5 투어 요약 (신설, 핵심)
```
                 3장 중 2장 맞히셨습니다              ← Jua, 이 화면의 유일한 Jua

   [썸네일]          [썸네일]          [썸네일]
   날개불구 ✓         응애 ✗            정상 ✓
   보이는 병         안 보이는 병        함정

   1장은 눈에 보이니까요. 2장부터는 사람 눈으로는 어렵습니다.
   HelpBee 는 3장 다 찾았습니다.

                              [ 더 해보기 ]   [ QR 받기 → ]
```
썸네일은 박스 없이 사진만. ✓/✗ 는 관람객 추측 기준. 건너뛴 라운드는 `—`.
맞힌 수에 따라 첫 줄이 바뀐다: 0장 "한 장도 못 찾으셨죠 — 정상입니다." / 3장 "3장 다 맞히셨습니다. 눈이 좋으시네요."

### 4.6 자유 선택 (기존 picker, 보너스)
10장 그리드 **5열 × 2행**. 카드 번호·"이 사진으로 진단하기" 라벨 유지. 여기서 들어간 결과 화면은 `마치기 →` → 마무리.

### 4.7 삭제
- `history_screen.dart`, `trend_chart.dart`, 관련 테스트, `BoothSession.seedScores`/`chartScores`.

## 5. 바운딩 박스 (`bbox_overlay.dart`)

- **직각 모서리, 2px.** 응애 `tierDanger` / 다른 병 **주황(신규 토큰 `boxDisease`)** / 정상 `tierSafe` alpha 0.7.
- **라벨 태그**: 박스 좌상단 바깥쪽에 채운 사각형 + 12~13pt 흰 글씨. 문구는 `응애`·`날개불구`·`석고병`·`정상`. 태그가 이미지 상단을 벗어나면 박스 안쪽 좌상단으로.
- **신뢰도 숫자 없음** — 추론을 돌리지 않으므로 지어낸 수치가 된다.
- **등장**: 테두리가 좌상단에서 시계방향으로 한 바퀴 그려진 뒤(`Path` 부분 그리기) 태그가 붙는다. 페이드·축소 없음.
- 순서는 유지: 정상 먼저 → 다른 병 → 응애 마지막.
- 타이밍 계산(`boxProgressAt`/`totalMs`/`revealOrder`)은 순수 함수 유지 + 테스트.

## 11. 구현 중 설계 정정 (2026-09-08, 실측 반영)

구현하면서 이 설계 문서의 세 군데가 사실과 달랐다. 코드는 아래 기준으로 갔다.

1. **visible(다른 병) 케이스의 처방은 부스가 지어내지 않는다.** `risk.yaml` 의
   `recommendations.other_disease` 가 CLASS_OTHER > 0 일 때 자동으로 붙는다 — 그대로 쓴다.
   다만 그 문구는 목록 **뒤쪽**에 붙어서 첫 줄이 "응애 감염률이 안전 범위"가 되고, 제목이
   '석고병'인 화면에서 모순으로 읽혔다(웹 실측). 그래서 visible 에 한해 다른 질병 문구가
   시작되는 지점부터 끝까지를 앞으로 옮긴다(`BoothCase.orderedRecommendations`). 문구 자체는 안 건드린다.
2. **visible 케이스에는 티어 배지·게이지를 아예 그리지 않는다.** 응애가 0이라 `compute_risk()` 가
   `tier=safe` 를 주는데, 병든 벌통 화면에 '안전' 배지가 뜨면 정면으로 틀린 말이 된다.
3. **`isHealthy` 는 tier 가 아니라 `kind` 로 판단한다.** 같은 이유로 tier=safe 인 visible 케이스에
   '건강함' 추측이 정답 처리되던 버그가 있었다 — `kind == healthy` 만 건강이다.
