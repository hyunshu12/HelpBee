- 창업 캠프를 지나가는 **일반인**. 학생·지역 주민·타 팀 참가자.

**1인 체류 40~50초.** 어느 화면이든 **60초 무동작이면 [0]으로 복귀**한다.

### [5-a] 기록 보기 — "기록"의 정의

결과 화면 우하단 `[기록 보기]`로만 들어가는 곁가지 화면. 메인 흐름이 아니다.

- **미리 심어둔 과거 4주치 4점**(고정값) + **이번 세션에 관람객이 진단한 건**이 뒤에 얹힌다.
- 1점짜리 밋밋한 그래프를 피하기 위한 장치다. 관람객이 위험 사진을 고르면 마지막 점이 확 치솟는다.
- **세션 초기화 시 관람객이 진단한 점만 지워지고, 심어둔 4점은 매번 복원된다.**
- 심어둔 4점은 실제 데이터가 아니므로 화면에 **"예시 기록"** 이라고 작게 표기한다.

### 설계 의도

- **[3]이 이 부스의 유일한 참여 지점이다.** 관람객이 직접 판단하고 → AI가 답을 준다.
  사업계획서 Q5의 *"우리가 없애는 건 내검이 아니라 판독"* 을 관람객이 몸으로 겪는 구간.
  줄이 길면 `[바로 결과 보기]`로 건너뛴다.
- 정상 사진을 골라 "건강함"을 맞히면 *"정확합니다! 이 벌통은 건강합니다"* 로 기분 좋게 끝낸다.
  틀렸을 때 톤은 **위로**("전문가도 어렵습니다"), 절대 조롱하지 않는다.

## 5. 결과 수치는 어떻게 나오는가

모델 추론을 돌리지 않는다. **정답 라벨 → 프로덕션 코드가 계산**한다.

```
AI Hub 라벨 JSON (category_id 0~6, COCO bbox)
   │ training/data/aihub_to_yolo.py : CLASS_MAPPING   (7-class → 3-class)
   ▼
class_counts {0: normal, 1: varroa, 2: other}
   │ app/services/risk.py : compute_risk()            ← 프로덕션 코드 그대로 호출
   ▼
risk_score · tier · recommendations[]  →  assets/cases.json
```

**risk·티어·처방 문구를 손으로 적지 않는다.** `risk.yaml`이 바뀌면 스크립트만 다시 돌리면
되고, 문구가 실제 앱과 영원히 어긋나지 않는다.

### 검증 완료 (2026-08-30)

기존 `demo-assets/` 6장으로 대조한 결과 — 라벨 기준 수치가 **실제 앱 E2E 값과 티어 전부 일치**:

## 6. bbox 포맷 정정 (2026-08-30) — 이 절은 한 번 뒤집혔다

### 무슨 일이 있었나

설계 초안에서 "응애 라벨 박스는 벌 여러 마리를 포함하는 거대한 영역이라 전부 그리면 화면이
덮인다, 그러니 응애 박스만 그리자"고 판단했다. **그 관찰은 틀렸다.**

AI Hub 71667 의 `bbox` 는 `[x, y, w, h]` 가 아니라 **`[x1, y1, x2, y2]`** 다. 문서와
`training/data/aihub_to_yolo.py` 가 전자로 취급하고 있어서, 그 코드를 그대로 따라간 초기 분석의
박스가 전부 부풀려져 있었다.

- 근거·영향·처리 계획: **[`docs/03-refactoring/2026-08-30-aihub-bbox-format-misparse.md`](../docs/03-refactoring/2026-08-30-aihub-bbox-format-misparse.md)**
- 요약: 4210개 annotation 중 4208개(100.0%)가 xyxy 로 `area` 필드와 일치. 면적 중앙값이
  0.7%(정답) vs 8.4%(오독)로 12배 차이.

### 정정 후 사실

| 초안의 판단 | 정정 후 |
|---|---|
| 박스가 벌 여러 마리를 덮는다 | ❌ **박스는 벌 한 마리씩 정확히 감싼다** (육안 확인) |
| 박스 76%가 화면 밖으로 잘린다 | ❌ 정답 좌표에서 경계를 넘는 이미지는 174장 중 1장 |
| 그러니 응애 박스만 그린다 | ❌ **전부 그린다.** 응애 빨강 / 정상 초록 |
| risk 100 은 박스가 겹쳐서 못 쓴다 | ❌ **쓸 수 있다.** 히어로 사진으로 복귀 |

### 그래도 남아 있는 제약

- **응애 확대(줌인)는 여전히 하지 않는다.** 정답 좌표로 크롭해도 원본이 어둡고 흔들려
  배 위의 검붉은 타원이 "응애로 보인다" 수준이다. 관람객에게 "여기 있습니다"라고 단언할
  선명도가 아니다. 박스 표시까지가 이 데이터로 할 수 있는 연출의 끝이다.
- **[1] 응애 소개 화면은 별도 사진이 필요하다.** 진단용 4장에서는 응애를 짚어 보여줄 수 없고,
  `유충_응애/046` 클로즈업만 육안 식별이 된다 (§4).
- **[3] 질문은 "이 벌통, 건강해 보이나요?"** 를 유지한다. "응애를 찾아보세요"로 되돌리지 말 것 —
  결과 화면에서도 응애 자체는 또렷하지 않아 관람객이 확인할 방법이 없다.

### 외부 패키지를 쓰지 않는 이유

네트워크·카메라·보안저장소를 쓰지 않으므로 `dio`/`camera`/`flutter_secure_storage`가

→ **`flutter build web`이 깨질 지점이 사라진다.** "네이티브 + 웹 백업"을 사실상 공짜로
만드는 결정이다.

## 7. 2026-08-31 — 디자인 시스템 재작업

첫 구현은 기능은 다 맞았지만 화면이 "PPT 슬라이드" 처럼 보였다. 원인과 처방을 남긴다.

### 7.1 근본 원인 — 토큰만 복사하고 스킴에 연결하지 않았다

`apps/mobile` 의 `AppColors` 를 그대로 가져왔지만, 테마는 `ColorScheme.fromSeed(honeyBrand)`
결과를 **그대로** 썼다. M3 톤 팔레트가 노란 시드에서 뽑는 `primary` 는 **`#755B0B`(탁한 올리브
갈색)** 이라, 화면의 모든 `FilledButton` 이 꿀색이 아니라 진갈색으로 칠해져 있었다.
`apps/mobile/lib/core/theme/app_theme.dart` 는 `.copyWith(primary: honeyPrimary, ...)` 로
시드 결과를 덮어쓴다 — 부스 앱에는 그 한 줄이 빠져 있었다.

→ 회귀 테스트: `test/theme_test.dart` ("primary 는 시드 파생색이 아니라 honeyPrimary 토큰 그대로다")

### 7.2 그 외 구조적 결함

| 문제 | 처방 |
|---|---|
| 모든 화면이 `Padding(Column(...))` — 면·층·브랜드가 없다 | `BoothScaffold`(공통 틀 + 워드마크 + 벌집 배경) · `BoothCard` · `PhotoFrame` · `HoneyChip` · `TierBadge` 신설 |
| 사진이 배경에 그대로 붙어 "붙여넣은 이미지" 로 보임 | `PhotoFrame` — 둥근 클립 + 흰 매트 + **따뜻한 갈색** 그림자(회색 금지) |
| 보조 버튼이 스타일 없는 `TextButton` 이라 그냥 글자로 보임 | 테마에서 옅은 꿀색 알약 + 테두리로 통일 |
| 화면 전체가 밝은 크림 일색이라 멀리서 안 걸림 | 어트랙트·마무리를 **다크 스테이지**로 (모바일 스플래시와 같은 `#18130C`) |
| 결과 화면에 티어가 게이지 캡션 + 배지로 **두 번** | 배지 하나로. 게이지 `caption` 은 선택 인자로 강등 |

### 7.3 웹 백업의 치명적 결함 — 한글이 두부(□)로 뜬다

**Flutter Web(CanvasKit)은 번들 폰트에 없는 글리프를 런타임에 `fonts.gstatic.com` 에서
받아온다.** 부스 앱은 Jua(표시용)만 번들하고 본문은 "플랫폼 시스템 폰트" 에 맡겼는데,
웹에는 그런 게 없다. 실측 결과 `notosanskr` woff2 **5조각**을 CDN 에서 받아가고 있었고,
그 사이 본문이 전부 두부로 보였다. 웹 백업은 정확히 "네이티브가 안 될 때" 를 위한 것이라,
부스 Wi-Fi 가 흔들리면 백업이 백업 구실을 못 한다.

처방:
- `tool/build_body_font.py` — Noto Sans KR(OFL)을 **앱이 실제로 쓰는 글자 ∪ Jua 의 한글
  커버리지(≈KS X 1001 2350자)** 로 서브셋해 400/700 두 정적 인스턴스로 굽는다. 각 ~490KB.
- 테마의 본문 슬롯 + `ThemeData.fontFamily` 에 못박고, 폴백으로 Jua 를 단다.
- `flutter build web --release --no-web-resources-cdn` — CanvasKit 자체도 번들에서 서빙.
- ⚠️ **`TextPainter` 는 위젯 트리 밖이라 테마를 상속하지 않는다.** 추이 그래프의
  `위험 70+` 라벨이 이 함정에 빠져 혼자 두부였다 → `lib/theme/app_fonts.dart` 상수를
  명시하도록 고치고 테스트로 고정.

→ 회귀 테스트: `test/fonts_test.dart`

### 7.4 고정 캔버스 가정이 깨지던 지점들

실기기 없이 확인하려고 웹 빌드를 브라우저에서 클릭해 돌면서 찾은 것들:

- **사진 고르기 카드 3·4 가 통째로 잘려 누를 수 없었다** — `GridView.count` +
  고정 `childAspectRatio`. 캔버스가 가정보다 조금만 짧으면 아래 줄이 사라진다.
  → `Expanded` 2x2 로 교체(남은 공간이 얼마든 항상 채우고 절대 넘치지 않는다).
- **추측·결과 화면 사진이 컬럼 폭을 못 채움** — `CrossAxisAlignment.start` 아래에서
  `PhotoFrame` 이 가로로 shrink-wrap. → `stretch`.
- **사진 위아래 흰 띠 110px** — 액자만 부모 높이로 늘어나고 사진은 `contain` 으로 가운데
  정렬. → `PhotoFrame(aspectRatio:)` 로 액자가 사진 비율에 붙게.
- **어트랙트가 짧은 캔버스에서 61px 넘침** → 게이지 컬럼을 `FittedBox(scaleDown)`.

→ 회귀 테스트: `test/layout_overflow_test.dart` — **화면 8개 × 캔버스 2종(1366x1024,
1280x720) 오버플로 스윕.** 화면마다 테스트를 따로 두면 새 화면에서 빠지므로 한 곳에서 쓴다.

### 7.5 검증 방법 (다음 작업자에게)

## 8. 2026-09-08 — 경량화 · 배터리

부스는 아이패드 한 대로 **하루 종일** 돌아간다. 화면 밝기 다음으로 배터리를
먹는 게 애니메이션인데, 코드로 통제 가능한 건 이쪽뿐이다.

### 8.1 어트랙트가 전부다

어트랙트는 관람객이 없는 **하루의 대부분**을 차지한다. 여기서 세 가지가 낭비였다:

| 문제 | 처방 |
|---|---|
| 안내 칩 맥박이 `repeat(reverse: true)` — **하루 종일 60fps** | 4초 주기마다 1.2초만 뛰고 멈춘다. 나머지 2.8초는 **프레임을 아예 요청하지 않는다** |
| 4초마다 `key: ValueKey(_replay)` 로 `BboxOverlay` 를 통째로 재생성 → State·컨트롤러·이미지가 매번 새로 (8시간이면 7,200번) | `replay` 프로퍼티로 바꿔 컨트롤러만 되감는다 |
| `RepaintBoundary` 0건 — 펄스 한 번에 사진과 게이지 블러가 같이 다시 그려짐 | 사진·게이지를 각각 독립 레이어로 |

**실측: 애니메이션 가동률 100% → 30%** (12초 중 12초 → 3.6초).
`WidgetTester.binding.hasScheduledFrame` 로 "앱이 프레임을 요청하는가"를 직접
재는 테스트가 `test/attract_idle_test.dart` 에 있다 — 배터리의 직접 지표다.

### 8.2 앱 크기 18.6MB → 16.8MB

`Jua-Regular.ttf` **2,070KB → 288KB**. 표시용 서체라 헤드라인·숫자에만 쓰는데
글리프 2,519자를 통째로 싣고 있었다. 앱이 실제로 쓰는 글자만 남긴다.

폴백 설계가 함께 바뀌었다 (`lib/theme/app_fonts.dart`):
- **Noto = 넓게** (앱이 쓰는 글자 + 상용 한글 2,367자) → 본문
- **Jua = 좁게** (지금 화면에 있는 글자만) → 표시용
- **표시용의 폴백은 Noto** — 나중에 헤드라인에 새 글자가 들어와도 두부가 아니라
  Noto 로 그려진다. 서체는 달라져도 읽을 수는 있다.

굽는 법: `python3 tool/build_fonts.py --noto <원본> --jua <원본>`
(둘 다 OFL. 원본 URL은 스크립트 docstring에. 서브셋에 글자가 빠지면 **빌드가 실패**한다.)

### 8.3 사진은 건드리지 않았다

1600×900인데 부스 기기에서 **약 2500 물리픽셀 폭**으로 그려진다 — 이미 확대해
쓰는 중이라 더 줄이면 화질만 나빠진다. 관람객이 눈으로 응애를 찾는 화면이라
400KB와 바꿀 것이 아니다. 사진 1.3MB는 **의도적으로 남긴 비용**이다.
