## 1. 목표 아키텍처

```
                         ┌──────────────────────────────┐
  양봉가(모바일 앱) ──────▶│  Cloudflare (무료)            │
  웹 방문자      ──────▶│  DNS + 프록시 + Universal SSL │
                         └──────┬───────────┬───────────┘
                                │           │ (DNS only)
                    api.helpbee.kr      www/admin.helpbee.kr
                                │           │
                                ▼           ▼
              ┌─────────────────────┐   ┌──────────┐
              │ EC2 t3.medium (x86) │   │  Vercel  │
              │ ┌─────────────────┐ │   │ web/admin│
              │ │ Caddy (Origin CA)│ │   └──────────┘
              │ ├─────────────────┤ │
              │ │ api  (Hono)     │─┼──────▶ RDS PostgreSQL 16
              │ │ ai   (FastAPI/  │ │        db.t4g.micro (단일AZ,
              │ │       ONNX CPU) │ │        자동백업 7일 + PITR)
              │ │ redis (컨테이너) │ │
              │ └─────────────────┘ │──────▶ S3 (images / models / tf-state / db-backups)
              └─────────────────────┘
                        ▲
              GHA: build → ECR push ──▶ SSM Run Command로 pull & up
```

- **배포 흐름**: PR → develop 머지 → `ci.yml` green → `deploy-beta.yml`(workflow_dispatch 또는 workflow_run + Environment 승인) → OIDC로 AWS 인증 → docker build → ECR push(git SHA 태그) → SSM Run Command로 EC2에서 `ecr login → compose pull → migrate(1회성 컨테이너) → up -d → /health 확인`
- **롤백**: `workflow_dispatch`에 image_tag 입력 → 이전 SHA 재배포
- **마이그레이션**: `packages/database/src/migrate.ts`(이미 인프라 중립)를 EC2 로컬에서 실행 — DB를 인터넷에 노출하지 않음

## 3. 선행 조건 — 사람(사용자) 액션 P0

인프라 코드 작업보다 먼저, 또는 병행으로 사용자가 직접 처리해야 하는 항목:

1. **AWS ROOT 키 회전 + MFA + CloudTrail 활성화** ← 2026-06-08/11 메모의 미해결 P0. 이거 안 하고 OIDC/instance profile을 얹으면 잠재 침해 위에 공격 표면만 넓히는 것.
2. **helpbee.kr 도메인 구매** (가비아, 연 ₩13,000~22,000) ← 이 항목 하나가 Cloudflare DNS·TLS·**Resend 이메일 인증(베타 온보딩)** 을 동시에 블로킹 중. 구매 후 네임서버를 Cloudflare로 교체하고, Resend SPF/DKIM/DMARC 3레코드를 같은 작업에서 등록(런북 `docs/04-operation/email-verification-runbook.md` §4 연계).
3. **관리자 권한으로 AWS 리소스 재고 1회 확인** — 이번 감사의 IAM(`claude_helpBee`)은 S3 외 전부 AccessDenied라 "없음"이 아니라 "확인 불가". 콘솔에 이미 만들어져 방치된 EC2/Route53/ACM/OIDC가 있는지(숨은 비용) 확인.
4. **부트스트랩용 관리자 자격증명 확보** — GHA OIDC IdP + IAM Role 생성, tf state 버킷 생성은 `claude_helpBee` 권한으로 불가능. 사람이 1회 수행(또는 Claude에게 일시적 권한 부여) 후 Terraform import로 코드화.
5. **Vercel 프로젝트 생성** (web/admin 각각, Root Directory 지정, production 브랜치=develop) + Pro 플랜 결정(§7).

## 4. 실행 계획 (PR 단위, 순서대로)

> 모든 변경은 feature 브랜치 → PR → develop. Terraform은 plan diff를 PR 본문에 첨부, apply는 사람만.

### PR-1. `fix(api): build 스크립트 버그` — 즉시
- `apps/api/package.json`의 `"build": "tsc && node dist/index.js"` → `"tsc"` (서버 실행은 기존 `start`가 담당).
- **이 버그 때문에 표준 멀티스테이지 Dockerfile(`RUN pnpm build`)이 빌드 중 서버를 실행하며 hang/크래시** — 컨테이너화의 선결 조건.

### PR-2. `chore(infra): Terraform bootstrap` — state 기반
- `infra/terraform/bootstrap/`: S3 state 버킷(**`helpbee-tf-state`로 이름 통일** — 기존 `environments/`의 `helpbee-terraform-state` 참조 폐기) + versioning + SSE + Public Access Block + DynamoDB lock 테이블. 로컬 backend로 작성(닭-달걀 회피), 생성 후 self-migrate.
- 부트스트랩 tfstate는 커밋 금지.

### PR-3. `feat(infra): 절감 모드 Terraform — envs/beta`
- `infra/terraform/envs/beta/` (staging이라는 이름 대신 **beta** — 실사용자 데이터가 사는 환경임을 명명으로 표현):
  - **default VPC** 재사용(data source) — 기존 vpc 모듈은 NAT GW를 무조건 생성(AZ당 상시과금)하므로 사용 금지
  - `modules/ec2`: t3.medium + EIP + SG(인바운드 80/443만, 22 미개방) + IAM instance profile(SSM Core, ECR pull, S3 images/models 한정, ssm:GetParameters)
  - `modules/ecr`: helpbee-api, helpbee-ai (IMMUTABLE 태그, lifecycle 20태그)
  - `modules/rds`: db.t4g.micro (기존 rds 모듈 뼈대 재사용 가능하나 구 VPC 결합 제거), SG는 EC2 SG에서만 인바운드 5432
  - S3: 기존 `helpbee-images-dev` **Terraform import + versioning 활성화 + 용도 재정의**(beta 실데이터용 개명 또는 태깅), `helpbee-db-backups` 신설(lifecycle 14일)
  - user-data: SSM SecureString → `/opt/helpbee/.env`(600) 렌더링 + CloudWatch Agent 설치 + AI 모델 캐시 디렉터리(`/opt/helpbee/cache/yolo`) 준비
- GHA OIDC IdP + 배포 role(trust는 `repo:hyunshu12/HelpBee:ref:refs/heads/develop` + environment로 좁힘 — **public 리포라 필수**)은 사람이 1회 생성 후 import.

### PR-4. `feat: Dockerfile (api, ai) + docker-compose.beta.yml + Caddyfile`
- `apps/api/Dockerfile`: node:20-alpine multi-stage (`turbo prune --scope=@helpbee/api` → deps → `tsc` build → runner: production deps + non-root + tini + HEALTHCHECK :3001/health). **sharp/argon2가 alpine(musl)에서 prebuilt 동작하는지 빌드로 실측 — 실패 시 slim(glibc)으로 전환.** 이미지에 `packages/database`(migrations 포함)를 포함해 EC2 로컬 마이그레이션 가능하게.
- `apps/ai/Dockerfile`: python:3.12-slim + `requirements.txt`만(torch 불필요 — CPU ONNX 스택, venv 실측 281MB → 이미지 400~600MB 예상). 시작 시 모델 warmup 1회 호출(콜드스타트 흡수).
- `docker-compose.beta.yml`: caddy + api + ai + redis(메모리 limit 명시). 이미지 태그 env 주입. AI 모델 캐시 bind mount(`/opt/helpbee/cache/yolo:/var/cache/helpbee/yolo`). `AI_INTERNAL_HMAC_SECRET`을 api/ai 양쪽 동일 주입.
- `infra/docker/caddy/Caddyfile`: Cloudflare Origin CA 인증서 서빙.
- **기존 `docker-compose.yml`(로컬용)의 평문 비밀번호는 변수 치환으로 교체** — 해당 문자열(`helpbee_password`)은 이미 git 히스토리에 있으므로 베타 환경에서 절대 재사용 금지.
- CI에 docker build 검증 job 추가(빌드되는지 PR 시점에 확인).

### PR-5. `feat(api): Cloudflare 대응 client-ip 재작성`
- `apps/api/src/lib/client-ip.ts` + `routes/auth.ts`의 XFF 파싱이 'CloudFront+ALB 2-hop'을 전제 — 그대로 배포하면 **IP 기반 레이트리밋·quota·audit_log.ip가 스푸핑 가능/무력화**.

### PR-6. `ci: deploy-beta.yml`

### 배포 후 검증 (베타 오픈 전 게이트)
- k6 부하: 동시 진단 업로드 시나리오 — **ONNX CPU 추론 동시성은 미검증 상태**(실측 ~200ms는 단일 요청 기준). p95 <2s 확인, 미달 시 t3.large 상향.
- E2E smoke: 로그인 → presign → S3 PUT → confirm → 분석 → recommendations 포함 결과 조회.
- 복원 드릴 1회 실행 (RDS 스냅샷 → 복원 → smoke).

## 6. 수용하는 리스크 (명시적 트레이드오프)

- **단일 EC2 = SPOF**: 장애 시 api+ai+redis 동시 다운. 베타 100명 규모에서 의도적으로 수용. 완화: EC2 status-check auto-recover 알람, AMI 스냅샷 주기 생성, UptimeRobot 즉시 알림. DB는 RDS 분리로 데이터는 보호됨.
- **베타 환경 = 사실상 프로덕션**: 이름은 beta지만 실사용자 데이터가 산다 — Environment 승인 게이트와 백업 정책은 프로덕션 기준 적용.
- **버스터블 인스턴스 크레딧 고갈** 시 성능 급락: 알람으로 감시, 지속 시 t3.large 상향(+$30~38).
- 비용 추정은 ±15% 오차 가능(ec2.shop 실측 기반이나 EBS/CloudWatch 단가는 근사) — 배포 후 첫 청구서로 재보정.
