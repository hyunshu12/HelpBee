## 1. 무엇이 잘못됐나

AI Hub 71667 라벨 JSON의 `bbox` 필드는 **`[x1, y1, x2, y2]`**(좌상단 + 우하단)인데,
문서와 코드가 전부 **COCO `[x, y, w, h]`**(좌상단 + 크기)로 취급하고 있다.

```python
# training/data/aihub_to_yolo.py:150
x, y, w, h = bbox          # ← 실제로는 x1, y1, x2, y2
...
x2 = min(float(img_w), float(x) + float(w))   # ← x1 + x2 를 계산하게 된다
y2 = min(float(img_h), float(y) + float(h))
```

`x2 > x1`이 항상 성립하므로 폭이 `x2 - x1`이 아니라 `x1 + x2`가 되어 박스가 크게 부풀고,
이미지 경계로 clip 된다.

## 2. 증거 (세 가지 독립 확인)

### 2-1. 라벨 자신의 `area` 필드 — 4210개 전수

| 해석 | `area`와 일치 |
|---|---|
| xywh (`x2 × y2`) | **14개 (0.3%)** |
| xyxy (`(x2−x1) × (y2−y1)`) | **4208개 (100.0%)** |

### 2-2. 문서의 자체 예시도 xyxy

`AIHUB_71667.md` §4에 실린 예시: `"bbox": [224.77, 413.65, 814.69, 1078.2]`, `"area": 392031`

- xywh: `814.69 × 1078.2 = 878,395` ✗
- xyxy: `(814.69−224.77) × (1078.2−413.65) = 392,043` ✓ (기록된 392,031과 일치)

### 2-3. 육안

`성충/성충_응애/089` 에 두 해석으로 박스를 그려 비교한 결과, xyxy 는 벌 한 마리씩 정확히 감싸고,
xywh 는 여러 마리를 포함하며 화면 밖으로 잘린다.

## 3. 학습 데이터에 실제로 일어난 일 (Sample 330장 기준)

| 지표 | 정답(xyxy) | 학습에 쓰인 값 |
|---|---|---|
| 박스 면적 중앙값 (이미지 대비) | **0.7%** | **8.4%** |
| 박스 면적 평균 | 1.8% | 10.4% |
| 경계를 넘어 잘린 박스 | 1 / 174 이미지 | **3204 / 4210 (76%)** |
| 작은 객체(<1% 면적) | **2910개 (69.1%)** | 35개로 기록됨 |

**면적이 중앙값 기준 12배 부풀려졌고, 박스의 76%가 잘린 채 학습됐다.**

## 4. 이 오류가 무너뜨리는 결론들

| 기존 결론 | 어디에 | 재검토 필요성 |
|---|---|---|
| 성충 응애 **미탐률 82%** | `plans/2026-08-12_시연-영상-계획.md` §5 | 부풀려진 라벨로 학습했으니 **유력한 원인**. 재학습 후 재측정 필요 |
| "Q3 = 케이스 B — 응애 자체 bbox 없음, 감염된 **벌 영역**" | `AIHUB_71667.md` §6 | 면적 중앙값이 0.7%면 '벌 영역'이 아니라 개별 객체 크기다. **판정 자체를 다시 봐야 한다** |
| "박스 크기가 거의 모두 medium~large" | `AIHUB_71667.md` §7 | 정답 기준 69%가 작은 객체 |
| "P2 head 불필요 (작은 객체 없음)" | ADR-0001 | **P2 head가 필요할 수 있다** |
| `infestation_rate` 를 VMIR 대신 쓴다는 설계 | `training/configs/risk.yaml` | 응애 개체 카운트가 가능해지면 표준 VMIR 재검토 여지 |

> ⚠️ `compute_risk()` 는 **인스턴스 개수만** 쓰고 bbox 기하는 쓰지 않는다. 따라서 저장된
> risk_score / tier / recommendations 값 자체는 이 버그의 영향을 받지 않는다. 영향은
> **학습된 검출기**와 **박스를 그리는 모든 것**에 한정된다.
