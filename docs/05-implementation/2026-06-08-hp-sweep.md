## 핵심 발견 — copy_paste는 이 데이터셋에서 no-op

`AIHUB_71667.md`가 "Copy-Paste 필수"라 했으나, 검증 결과 **틀림**:
- 라벨 21,542줄 **전부 bbox 전용(5 필드, segmentation 폴리곤 0개)**.
- ultralytics 8.3.253 `CopyPaste.__call__`이 `len(labels["instances"].segments) == 0`이면 즉시 return.
- → **copy_paste는 어떤 확률값에서도 동작하지 않음(no-op).** copy_paste를 올린 sweep config들의 효과는 동시에 바뀐 다른 knob(cls 등)에서 온 것.
- bbox 데이터에서 실제 작동하는 소수클래스/정규화 레버 = **mixup**. 진짜 oversampling은 instance resampling 또는 segmentation 마스크 생성 등 별도 기법 필요(후속).
- 본 PR에서 `AIHUB_71667.md` §7·§11의 copy_paste 문구를 정정.

## 최종 config 결정 — cls-heavy 강화 (200 epoch)

근거: risk = infestation_rate = 응애/(전체 벌)이라 **분모(bee_normal) 탐지 품질**이 golden에서 가장 취약(colony-001 과적합 → 정상 벌통이 'watch'로 상향 오분류 위험). cls-heavy가 val normal_AP50 최고(0.858)라 분모 보호에 강하고, 단일 검증 레버(cls)라 confound 표면이 가장 작다. sgd는 normal_AP50 0.724로 탈락, 광범위 증강(reg-generalize)은 varroa_recall까지 하락(0.957)해 탈락.

`_final_config.yaml` overrides (yolo.yaml 대비):

| key | value | 이유 |
|---|---|---|
| cls | 1.5 | 지배 검증 레버 (numerator+denominator 동시 보호) |
| dfl | 1.5 | (=기본, 명시) box 분포 품질 |
| mixup | 0.2 | bbox에서 실작동하는 소수노출/정규화 레버 (copy_paste 대체) |
| close_mosaic | 20 | 200ep의 ~10% mosaic-off tail (rate 분모용 깨끗한 box 통계 회복) |

고정: copy_paste 0.3(no-op·유지), box 7.5, hsv_h 0.015(응애 색=진단 단서), imgsz 640, yolo11s (ADR-0001).

의사결정은 8-에이전트 다관점 워크플로(4 렌즈 분석 + 3 적대 비평 + 1 종합)로 수행. confidence 0.74. 패널 다수는 recall-aggressive를 선호했으나, 적대 비평이 copy_paste no-op을 발견해 그 우위 근거가 무너지며 cls-heavy로 수렴.
